# OBC control-sequence verification

Run `python -m pip install -r verification/requirements.txt`, then `python scripts/verify-obc.py` from the repository root. The command replays each archived input trend through both the Rust compatibility `Executor` and the compiled executor used by the browser, writes both observed output trends, and uses LBNL's [pyfunnel](https://github.com/lbl-srg/funnel) to compare each with the reference output at the declared time and value tolerances. A nonzero funnel excess in either path fails CI. The `verification/results/` directory contains each actual trace, funnel bounds, errors, and a summary.

Most reference CSV values were independently calculated from the equations in the [Modelica Buildings CDL blocks](https://github.com/lbl-srg/modelica-buildings/tree/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Controls/OBC/CDL), pinned to commit `d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7`. The SampleTrigger period and shifted-period traces are calculated from the pinned `y = sample(t0, period)` source equation with the same 0.5-second period and 1.3-second shift as the official validation model. A discrete runtime reports a one-step pulse at the first step that reaches each event; these fixtures land exactly on the sample times. The BooleanToReal trace contains the 101 input/output samples from the pinned [Dymola validation result](https://github.com/lbl-srg/modelica-buildings/blob/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Resources/ReferenceResults/Dymola/Buildings_Controls_OBC_CDL_Conversions_Validation_BooleanToReal.txt), sampled over four seconds. The three TrueFalseHold traces are the 101-point `truFalHol`, `truFalHol1`, and `truFalHol4` input and output series from the pinned [Dymola validation result](https://github.com/lbl-srg/modelica-buildings/blob/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Resources/ReferenceResults/Dymola/Buildings_Controls_OBC_CDL_Logical_Validation_TrueFalseHold.txt), sampled every 72 seconds. Their 72-second time tolerance accounts for input events between those samples; no Boolean value error is permitted outside that time window. The editable G36 zone-status composite uses four output series for both window-sensor variants from the pinned [Dymola ZoneStatus validation result](https://github.com/lbl-srg/modelica-buildings/blob/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Resources/ReferenceResults/Dymola/Buildings_Controls_OBC_ASHRAE_G36_ZoneGroups_Validation_ZoneStatus.txt). The archived result is `g36_zone_status_dymola.txt`; `python scripts/generate_zone_status_reference.py` extracts the eight 101-sample CSVs, and the verification command checks them for drift. The four recorded outputs match with zero time or value tolerance in both Rust executors, both in the standalone example and in a `zone_status_1` instance extracted from the bundled G36 graph. The latter cases use the same archived traces with `input_offsets` of −273.15 K on the five temperature inputs to exercise the building’s °C-valued ports; the source differences and Boolean decisions must remain identical. The `source` field in `suite.json` identifies the source for each case. These values are checked into the repository; the verification run does not generate its own expected outputs. The P controller/limiter case uses the checked-in graph and the official MultiplyByParameter and Min equations.


The editable OBC `OperationMode` reference is generated from the pinned [Modelica source](https://github.com/lbl-srg/modelica-buildings/blob/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Controls/OBC/ASHRAE/G36/ZoneGroups/OperationMode.mo), archived as `g36_operation_mode_modelica.mo`. Its two message-only `Assert` blocks are omitted; all control-producing blocks and wires are retained. The one-zone [Dymola validation result](https://github.com/lbl-srg/modelica-buildings/blob/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Resources/ReferenceResults/Dymola/Buildings_Controls_OBC_ASHRAE_G36_ZoneGroups_Validation_OperationMode.txt) is archived as `g36_operation_mode_dymola.txt`. `python scripts/generate_operation_mode_reference.py` reconstructs the validation model's comparator inputs from its recorded zone temperature and creates a second trace with five identical zones and a °C temperature adapter. Both Rust executors match all 101 recorded mode samples in the standalone composite and the composite extracted from the bundled building. The pinned Modelica source and result are distributed under the [Modelica Buildings license](modelica-buildings-License.mo). The building adds separate editable CDL priority switches to resolve simultaneous mode requests; the pinned result does not exercise every overlap or fault condition.

The editable GroupStatus graph expands the pinned [Modelica source](https://github.com/lbl-srg/modelica-buildings/blob/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Controls/OBC/ASHRAE/G36/ZoneGroups/GroupStatus.mo) vector filters into scalar zone ports and its multi-input reductions into CDL chains. The archived [Dymola validation result](https://github.com/lbl-srg/modelica-buildings/blob/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Resources/ReferenceResults/Dymola/Buildings_Controls_OBC_ASHRAE_G36_ZoneGroups_Validation_GroupStatus.txt) uses a two-of-three-zone mask. `python scripts/generate_group_status_reference.py` reconstructs its unrecorded constant inputs from the pinned validation model and checks 11 recorded outputs at 101 samples in the dynamic and compiled Rust paths. The source divides its group temperature sum by the total building-zone count, including when the mask excludes a zone; the flattened graph preserves that behavior. Ten recorded outputs are also replayed against the five-zone composite inside the bundled building, with three neutral extra zones and °C temperature ports. Other outputs are implemented from the source equations but lack recorded reference traces.

The historical zone-recovery case extracts `zone_group_1/optimal_warmup_1_learner` from `web/tests/fixtures/g36_pre_obc_optimal_start.json`, the frozen graph immediately before OBC optimal-start integration. The shipped G36 group now uses ten pinned OBC optimal-start composites per five-zone group. Its 60-second, four-day input trend contains three measured recovery episodes and a day when no start is needed. The expected rate follows the [pinned OBC OptimalStartCalculation slope, moving-mean, and floor equations](https://github.com/lbl-srg/modelica-buildings/blob/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Controls/OBC/Utilities/BaseClasses/OptimalStartCalculation.mo): captured 3 K error divided by at least 120 seconds of recovery, the initial zero sample and last three daily samples, and a 1/3600 K/s minimum. `python scripts/generate_optimal_start_reference.py` regenerates the checked-in trend; the verification command checks it for drift. This tests the learner's bounded slope path under completed recoveries. It is a source-equation trace, not an independent Modelica run of the full optimal-start or zone-group composite.

The pinned [Dymola TimeSuppression positive-start result](https://github.com/lbl-srg/modelica-buildings/blob/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Resources/ReferenceResults/Dymola/Buildings_Controls_OBC_ASHRAE_G36_Generic_Validation_TimeSuppressionPositiveStartTime.txt) is archived as `g36_time_suppression_positive_dymola.txt`. The Rust `g36_sat_suppression_follows_pinned_obc_positive_start_trace` test drives the editable VAV suppression branch with the pinned validation model’s 22–27 °C ramp and 25 ± 2 °C sinusoidal zone temperature. Both executors match all 101 recorded `yAftSup` and `supTim.y` samples exactly at 72-second intervals. This covers one positive-time setpoint change; negative-time initialization and repeated changes still need independent traces.

The pinned [Dymola terminal SystemRequests result](https://github.com/lbl-srg/modelica-buildings/blob/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Resources/ReferenceResults/Dymola/Buildings_Controls_OBC_ASHRAE_G36_TerminalUnits_Reheat_Subsequences_Validation_SystemRequests.txt) is archived as `g36_system_requests_dymola.txt`. The Rust terminal hot-water test extracts the editable VAV request branch and compares its reset and plant requests at all 101 recorded 72-second samples in both executors. The reference keeps the discharge error in the two-request band and the valve below the plant threshold, so the same test separately exercises later rises to three requests, valve-only one request, and hysteresis clearing. The pinned [OBC TrueDelay source](https://github.com/lbl-srg/modelica-buildings/blob/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Controls/OBC/CDL/Logical/TrueDelay.mo) sets `delayOnInit=false`; the editable branch preserves its immediate initial request behavior. The complete combined SystemRequests outputs and 2024 Guideline 36 sequence still need independent validation.

Each CSV has `time_s`, one column per graph input, and `y` for the selected reference output. A case may name an `output` other than `y`, as for the Timer's `passed` connector. Values use CDL units; Boolean values are `0` and `1`. The configured tolerances are absolute. Timestamps must increase, and inputs and parameters remain the same for the Rust and reference series. This follows the [OBC time-series verification method](https://obc.lbl.gov/specification/verification.html) for control logic; it does not test physical point wiring or building performance.

The CI command also checks the pinned `OptimalStartCalculation` source checksum, its generated 32-block graph, and all bundled zone-group OBC instances and their input/output wiring. A Rust group trace checks cold-start mode selection and sensitivity to an edited OBC slope parameter in both executors. A two-day standalone trace also checks a completed 3 K recovery, the 1,740-second sampled duration, and the next-day 3,480-second start prediction against the pinned source equations in both executors. These checks do not substitute for an independent Modelica trace of the complete calculation.

Current coverage is BooleanToReal, Add, MultiplyByParameter, Limiter, Hysteresis, Real GreaterThreshold, Switch, TrueDelay, TrueFalseHold, Latch, UnitDelay, Sampler, Boolean Pre, TriggeredSampler, TriggeredMovingMean, SampleTrigger, Edge, FallingEdge, Timer, and the P limiter, recovery learner, ZoneStatus, OperationMode, and GroupStatus composites. It caught and corrected the Rust hysteresis polarity and the standard Switch connector order. The fixture set is a small subset of CDL. The pinned ZoneStatus result records four of the composite's eight outputs; the other four outputs still need independent reference traces. Modelica-generated traces for the complete optimal-start sequence, PID, Filter, and rate limiters remain next steps, as does unit conversion for BAS trends in non-SI units. Verification of the ten-zone building's plant and thermal model would need an independent system reference in addition to these control-logic traces.
