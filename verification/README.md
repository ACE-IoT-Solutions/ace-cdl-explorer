# OBC control-sequence verification

Run `python -m pip install -r verification/requirements.txt`, then `python scripts/verify-obc.py` from the repository root. The command replays each archived input trend through both the Rust compatibility `Executor` and the compiled executor used by the browser, writes both observed output trends, and uses LBNL's [pyfunnel](https://github.com/lbl-srg/funnel) to compare each with the reference output at the declared time and value tolerances. A nonzero funnel excess in either path fails CI. The `verification/results/` directory contains each actual trace, funnel bounds, errors, and a summary.

Most reference CSV values were independently calculated from the equations in the [Modelica Buildings CDL blocks](https://github.com/lbl-srg/modelica-buildings/tree/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Controls/OBC/CDL), pinned to commit `d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7`. The three TrueFalseHold traces are the 101-point `truFalHol`, `truFalHol1`, and `truFalHol4` input and output series from the pinned [Dymola validation result](https://github.com/lbl-srg/modelica-buildings/blob/d3d8e6f76514dfbc7d65574c6b5a777b686fe1b7/Buildings/Resources/ReferenceResults/Dymola/Buildings_Controls_OBC_CDL_Logical_Validation_TrueFalseHold.txt), sampled every 72 seconds. Their 72-second time tolerance accounts for input events between those samples; no Boolean value error is permitted outside that time window. The `source` field in `suite.json` identifies the source for each case. These values are checked into the repository; the verification run does not generate its own expected outputs. The composite case uses the checked-in P controller/limiter graph and the official MultiplyByParameter and Min equations.

Each CSV has `time_s`, one column per graph input, and `y` for the selected reference output. A case may name an `output` other than `y`, as for the Timer's `passed` connector. Values use CDL units; Boolean values are `0` and `1`. The configured tolerances are absolute. Timestamps must increase, and inputs and parameters remain the same for the Rust and reference series. This follows the [OBC time-series verification method](https://obc.lbl.gov/specification/verification.html) for control logic; it does not test physical point wiring or building performance.

Current coverage is Add, MultiplyByParameter, Limiter, Hysteresis, Switch, TrueDelay, TrueFalseHold, Latch, UnitDelay, TriggeredSampler, TriggeredMovingMean, Edge, FallingEdge, Timer, and one composite sequence. It caught and corrected the Rust hysteresis polarity and the standard Switch connector order. The fixture set is a small subset of CDL. Modelica-generated traces for the complete optimal-start sequence, PID, Filter, and rate limiters remain next steps, as does unit conversion for BAS trends in non-SI units. Verification of the ten-zone building's plant and thermal model would need an independent system reference in addition to these control-logic traces.
