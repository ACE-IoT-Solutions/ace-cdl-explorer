# Simulation totalizer audit

The four cumulative values shown in the simulation page are generated by `Simulation` in `runtime/src/lib.rs`. The comparison bars, current-run tiles, Worker message, JSON chunk, and saved run history do not independently integrate them.

| Value | Single source | Meaning |
| --- | --- | --- |
| Electricity (kWh) | `electricity_kwh` | Internal-step equipment electric power times step hours. |
| Boiler fuel (kWh input) | `gas_kwh` | Internal-step boiler fuel power times step hours. |
| Present-zone comfort exceedance (zone-hours) | `occupied_unmet_hours` | Zones outside 20–25°C while the schedule is occupied and the physical occupant count is positive. |
| All-zone comfort exceedance (zone-hours) | `unmet_hours` | Every zone outside 20–25°C during occupied schedule or 17–29°C otherwise. |

`simulation_totals()` serializes these fields for both `step_chunk()` and `summary_json()`. The Worker forwards `summary_json()` in each batch. Vue displays the latest worker summary during a run, then reads the completed run tiles and comparison bars from the same saved `runHistory` summary object through the shared `summaryMetrics` key list. Cancelling or failing a run clears the current summary and does not save a comparison record.

The screenshot's **837** zone-hours is a saved run's **present-zone** comfort, while **1,003** zone-hours in the lower tile is **all-zone** comfort. The latter also counts absent zones and off-schedule exceedance, so these values should differ. The screenshot can also compare two different run identities: older bars are saved snapshots, whereas the lower tiles describe the current run. Match the metric heading and run label before comparing numbers. Previously saved runs are not recalculated when the graph, scenario, or runtime changes. The matching bar and tile for the current completed run use the exact same saved summary object.

The 15-minute electricity and boiler chart rows and CSV contain mean power (kW), not separate cumulative totals. Each row is now derived from the change in the single cumulative kWh field since the previous row divided by 0.25 hours. A Rust test verifies that integrating those rows reproduces the summary across chunk boundaries and another verifies that the JSON and Worker summary transports agree. The instantaneous average-zone temperature and per-zone snapshots are separate state measurements, not totalizers.

Historical annual numbers in documentation and manual baseline scripts are reference replays. They are not loaded into the browser comparison. There is no browser-side energy or comfort re-integration from Arrow frames.
